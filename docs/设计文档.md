# ChatBook · 个人微信聊天记录整理与导出工具 — 产品设计文档

> 版本 v0.1 · 阶段：第一阶段（产品设计）+ 第二阶段（MVP 实现说明）
> 定位：**纯本地、离线、只处理用户主动提供数据**的聊天记录整理与导出工具。

---

## 1. 产品定位

把「我和某个好友的微信聊天记录」整理成**可阅读、可长期保存、可离线打开**的文档（HTML 阅读器 / Markdown / PDF）。

核心原则：

| 原则 | 落地方式 |
|---|---|
| 数据安全 | 所有处理在本机完成，无任何网络请求 |
| 本地离线 | SQLite 本地库 + 本地媒体库，导出为纯静态文件 |
| 隐私保护 | 不上传、不收集、可一键彻底删除 |

---

## 2. 合规红线（逐条对应约束）

| 用户约束 | 本设计对应决策 |
|---|---|
| 不使用微信机器人协议 | 不引入任何协议实现，无网络模块 |
| 不模拟微信登录 | 应用无登录概念，永不触碰微信账号体系 |
| 不调用非官方微信接口 | 代码中不存在任何 HTTP 请求微信服务的路径（渲染进程 CSP 禁止外联） |
| 不注入微信进程 / 不修改微信客户端文件 | 应用只读写自己的数据目录 `~/Documents/ChatBook/` |
| 不破解微信加密算法 | 明确不支持解析微信本地加密数据库（见 §3.1） |
| 不绕过微信安全机制 | 无任何绕过行为 |
| 不自动化操作微信客户端 | 无键盘/鼠标模拟、无 AppleScript 控制微信 |
| 只处理用户主动导出/授权/自己的数据 | 唯一数据入口 = 用户在界面中**亲手选择或拖入**的文件/文件夹 |

技术上的强制保障：

1. 主进程仅通过系统文件对话框与拖拽事件获得用户显式授权的路径；
2. 渲染进程开启 `contextIsolation`、关闭 `nodeIntegration`，页面 CSP 为 `default-src 'self'`，从根源上禁止外发数据；
3. 全工程无第三方网络库依赖。

## 3. 数据来源方案（核心设计）

### 3.1 现实约束的诚实说明

个人微信（消费版）**官方并没有提供「全文聊天记录导出」功能**：

- 「聊天记录备份到电脑」产出的是**加密备份包**，仅用于恢复，官方未公开格式——**本工具明确不支持解析它**（解析即破解加密，违反红线）；
- 微信本地数据库（Mac/Windows）同样加密，**同样明确不读**。

因此本工具的数据来源必须回到「用户能**合法、主动**拿到手的内容」。

### 3.2 方案 A：官方途径可获得的内容（MVP 支持其中 1/2/3）

| 途径 | 获得物 | 工具支持方式 |
|---|---|---|
| A1. 多选消息 → 复制/合并转发后复制 | 文本（含 `[图片]` 等占位符） | `微信复制格式` txt 解析器 |
| A2. 图片/视频/文件「另存为」 | 媒体文件 | 媒体文件夹导入 + 时间戳自动关联 |
| A3. 手动誊录/整理 | 任意 txt/json/csv | 对应解析器 |
| A4. 企业微信管理后台合规导出 | 结构化数据 | json/csv 解析器（字段别名兼容） |
| A5. 个人微信加密备份包 | — | **不支持，界面上明示原因** |

> 微信复制多选消息的实际格式（PC/Mac 端）：
> ```
> 张三 2026-09-20 21:30:15
> 你好，最近怎么样
>
> 我 2026-09-20 21:30:40
> 还不错
> ```
> 解析器按「昵称 + 日期时间」行头识别消息块，兼容 `[图片]` `[动画表情]` `[语音]` `[视频]` `[文件]` `[位置]` `[链接]` `[聊天记录]` 等占位符，占位符会被识别为对应消息类型（后续可关联真实媒体）。

### 3.3 方案 B：用户手动整理的标准格式（MVP 全部支持）

统一规范见 §6「数据格式规范」，包括：

- **txt**（两种：结构化「时间/发送者/内容」格式；微信复制格式）
- **json**（推荐，最完整：可声明会话元信息 + 消息数组 + 附件相对路径引用）
- **csv**（Excel 友好，表头字段名支持中英文别名）
- **html**（支持解析本工具导出的 HTML，实现「导出→再导入」闭环；也可手动按模板编写）
- **图片/视频/表情包文件夹**：递归收集 `.jpg/.jpeg/.png/.webp/.gif/.mp4/.mov/.m4a/.mp3/.wav/.pdf/.zip` 等文件

### 3.4 媒体文件 ↔ 消息 的关联策略（分三级）

1. **显式引用**（最可靠）：json/csv 中消息带 `file` 字段，路径相对于数据文件所在目录；
2. **文件名时间戳启发式**（自动，免整理）：
   - `2026-09-20_213015.jpg`、`20260920213015.jpg`、`IMG_20260920_213015.jpg`
   - `mmexport1695220215000.jpg`（微信另存，13 位毫秒时间戳）
   - 解析出拍摄时间后，与消息时间差 **≤ 120 秒** 的 `[图片]`/`[动画表情]` 占位消息自动关联（窗口可配）；
3. **手动关联**（第三阶段）：界面上对未关联媒体提供拖拽绑定。

无法关联的媒体进入「媒体池」（`media_pool` 表），不丢失、可后续处理。

### 3.5 方案 C：可扩展解析器接口

所有数据源实现统一接口（`src/main/parsers/types.ts`）：

```ts
export interface ChatParser {
  id: string
  name: string
  extensions: string[]                       // 声明可处理的扩展名
  canParse(ctx: ParseContext): boolean       // 内容嗅探：是否由我处理
  parse(ctx: ParseContext): ParseResult      // 解析为统一消息模型
}
```

注册表（`registry.ts`）按「扩展名过滤 → canParse 嗅探」选择解析器。新增数据源 = 新增一个文件实现该接口并注册，**不改动其他任何代码**。未来适配新合法来源（如企业微信导出格式升级、其他 IM 工具导出）都走这条路。

## 5. 技术架构与选型

| 项 | 选择 | 理由 |
|---|---|---|
| 桌面框架 | **Electron 33 + electron-vite** | Mac 优先且可扩展 Win/Linux；UI 生态最成熟 |
| UI | **React 18 + TypeScript**（Vite 构建） | 组件化开发阅读视图/导入向导；类型安全 |
| 数据库 | **better-sqlite3（SQLite + FTS5）** | 同步 API 简单可靠；FTS5 中文可搜（unicode61 分词 + 前缀匹配）；WAL 模式支持大批量 |
| PDF | Electron `webContents.printToPDF` | 复用 HTML 导出排版，零额外依赖 |
| 构建/打包 | electron-vite + electron-builder（dmg） | 标准方案 |

进程与安全模型：

- 主进程持有全部文件/数据库能力；渲染进程**只能**通过 preload 暴露的 `window.chatbook` 白名单 API 访问；
- `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true`；
- 渲染页面 CSP：`default-src 'self'; img-src 'self' file: data:`（file: 用于显示本地图片）；
- 拖拽文件取真实路径使用 `webUtils.getPathForFile`（Electron 官方推荐，`File.path` 已废弃）。

## 6. 数据格式规范（用户手动整理时的模板）

### 6.1 结构化 txt

```
时间：
2026-09-20 21:30:15

发送者：
好友昵称

内容：
你好，最近怎么样
```

- 「时间/发送者/内容」标签独占一行、值在下一行；也兼容「时间：xxx」同行写法；
- 内容可多行，直到下一个「时间：」标签结束；
- 占位符（`[图片]` 等）自动映射消息类型。

### 6.2 微信复制 txt

见 §3.2 示例。行头 `昵称 + 日期 时间` 开启新消息，其余非空行为内容。

### 6.3 json（推荐）

```json
{
  "conversation": { "title": "我和张三", "self": "我", "peer": "张三" },
  "messages": [
    { "time": "2026-09-20 21:30:15", "sender": "张三", "type": "text", "content": "你好" },
    { "time": "2026-09-20 21:31:00", "sender": "我", "type": "image", "file": "media/IMG_001.jpg" }
  ]
}
```

- 字段别名兼容：`time/timestamp/datetime/时间`、`sender/from/nick/发送者`、`type/message_type/类型`、`content/text/内容`、`file/file_path/attachment/附件`；
- `file` 相对路径基于 json 文件所在目录解析，导入时自动拷贝入媒体库。

### 6.4 csv

首行为表头（用中英文别名均可）：

```csv
时间,发送者,类型,内容,附件
2026-09-20 21:30:15,张三,文本,你好,
2026-09-20 21:31:00,我,图片,,media/IMG_001.jpg
```

### 6.5 html

支持解析**本工具导出的 HTML**（消息节点带 `data-*` 结构化属性），实现导出件归档后再导入的闭环。

## 7. 数据库设计（SQLite）

库文件：`~/Documents/ChatBook/chatbook.db`；媒体：`~/Documents/ChatBook/media/<会话id>/`。

```sql
-- 会话
CREATE TABLE conversation (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  title       TEXT NOT NULL,            -- 如「我和张三」
  self_name   TEXT,                     -- 我的显示名
  peer_name   TEXT,                     -- 对方显示名
  created_at  TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at  TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

-- 消息（按用户要求的核心字段）
CREATE TABLE chat_message (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  conversation_id INTEGER NOT NULL REFERENCES conversation(id) ON DELETE CASCADE,
  sender          TEXT,                 -- 发送者昵称
  sender_role     TEXT NOT NULL DEFAULT 'unknown',  -- self | peer | unknown
  message_type    TEXT NOT NULL DEFAULT 'text',
  content         TEXT,                 -- 文本内容 / 占位符说明
  file_path       TEXT,                 -- 首个附件相对路径
  timestamp       TEXT NOT NULL,        -- 本地时间 YYYY-MM-DD HH:mm:ss（可排序）
  created_time    TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  fingerprint     TEXT NOT NULL,        -- 去重指纹（增量导入核心）
  extra_json      TEXT                  -- 预留扩展（引用消息、位置等结构化内容）
);
CREATE UNIQUE INDEX idx_message_fingerprint ON chat_message(fingerprint);
CREATE INDEX idx_message_time ON chat_message(conversation_id, timestamp);

-- 附件（一对多）
CREATE TABLE message_attachment (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  message_id INTEGER NOT NULL REFERENCES chat_message(id) ON DELETE CASCADE,
  type       TEXT NOT NULL,             -- image | gif | video | voice | file
  path       TEXT NOT NULL,             -- 相对媒体库路径
  thumbnail  TEXT                       -- 缩略图路径（第三阶段生成）
);

-- 媒体池（已入库但可能尚未关联到消息的媒体）
CREATE TABLE media_pool (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  conversation_id INTEGER NOT NULL REFERENCES conversation(id) ON DELETE CASCADE,
  file_name       TEXT NOT NULL,
  path            TEXT NOT NULL,
  type            TEXT NOT NULL,
  taken_at        TEXT,                 -- 从文件名/时间戳推断的时间
  message_id      INTEGER REFERENCES chat_message(id) ON DELETE SET NULL,
  UNIQUE(conversation_id, file_name)
);

-- 导入批次（审计与增量导入）
CREATE TABLE import_batch (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  conversation_id INTEGER NOT NULL REFERENCES conversation(id) ON DELETE CASCADE,
  source_type     TEXT NOT NULL,
  source_path     TEXT NOT NULL,
  imported_at     TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  message_count   INTEGER NOT NULL DEFAULT 0,
  skipped_count   INTEGER NOT NULL DEFAULT 0,
  status          TEXT NOT NULL DEFAULT 'done'
);

-- 全文搜索（FTS5，内容外链表 + 触发器同步）
CREATE VIRTUAL TABLE message_fts USING fts5(
  content, sender,
  content='chat_message', content_rowid='id', tokenize='unicode61'
);
-- 附 INSERT/UPDATE/DELETE 触发器保持同步（见 schema 实现）
```

关键机制：

- **增量导入**：`fingerprint = sha1(会话id|发送者|类型|时间|内容|附件路径)`，`UNIQUE` 索引 + `INSERT OR IGNORE`，重复导入自动跳过并计数；若新导入为旧消息补充了附件，会自动回填 `file_path` 与附件行；
- **快速搜索**：FTS5 全文索引，用户输入按词加引号 + 前缀 `*` 处理，规避 FTS 语法注入；命中用 `snippet()` 生成上下文片段；另提供「前后 N 条」上下文查询；
- **可加密**（第三阶段）：默认 SQLCipher 方案（`better-sqlite3` sqlcipher 分支）或应用层对库文件 AES 加密，密钥存 macOS Keychain。

单窗口三区布局（macOS 风格）：

```
┌────────────┬──────────────────────────────────────┐
│  会话列表    │  工具栏: 🔍搜索 │ 发送人▾ │ 类型▾ │ 导出▾ │
│            ├──────────────────────────────────────┤
│  +导入      │                                      │
│  ● 我和张三  │      2026-09-20 星期日                │

└────────────┴──────────────────────────────────────┘
```

- **导入向导**（弹窗）：选择「新建会话/导入到已有会话」→ 填标题/我的昵称/对方昵称 → 拖拽数据文件 + 选择/拖入媒体文件夹 → 实时进度条（阶段/当前/总数/明细）→ 结果摘要（新增/跳过/警告）；

- **删除**：会话级彻底删除（数据库行 + 媒体文件 + 目录）。

## 9. 导出格式设计

### 9.1 HTML 阅读器（重点）

产出目录：`<导出目录>/聊天记录-<会话名>/index.html (+ assets/)`，或单文件（图片 base64 内嵌，适合归档单文件长期保存）。

功能：日期分组头（`2026-09-20 星期日`）→ 消息（时间 + 发送人 + 气泡）→ 页脚统计；**纯静态零依赖**（无 CDN、无外链、file:// 双击即开），内置：

- 关键词搜索（客户端 JS 过滤 + `<mark>` 高亮 + 命中计数）；
- 发送人筛选（全部/我/对方）；
- 类型筛选（文本/图片/表情…）；
- 日期跳转导航；
- 图片缩略 + 点击灯箱查看原图；
- `@media print` 打印样式（供浏览器打印/另存 PDF）。

### 9.2 Markdown

```
# 我和张三聊天记录
## 2026-09-20 星期日
### 21:30 · 我
今天工作怎么样？
### 21:31 · 张三
还不错
```
图片/表情以 `![](assets/xxx)` 相对引用（同目录拷贝 assets）。

### 9.3 PDF

复用 HTML 阅读器排版，`webContents.printToPDF`（A4、背景色、页边距、`page-break-inside: avoid`）输出。

## 10. 安全与隐私设计清单

- [x] 无任何网络请求代码；渲染进程 CSP 禁止外联
- [x] 数据目录唯一且明确（`~/Documents/ChatBook/`），删除功能覆盖 DB 行 + 媒体文件 + 空目录
- [x] 只访问用户通过对话框/拖拽显式授权的路径
- [x] 拖拽路径获取用 `webUtils.getPathForFile`，不启用任何全局文件监听
- [ ] 数据库加密（第三阶段，Keychain 存密钥）
- [x] 导出的 HTML 无脚本外链、无统计代码

## 12. 开发步骤（三阶段）

**第一阶段 · 产品设计（本文档）** ✅

## 13. 后续扩展方案

## 14. 风险与边界

| 风险 | 应对 |
|---|---|
| 用户误以为能读微信加密库 | 界面与文档双重明示不支持，并解释原因 |
| 手动整理格式千差万别 | 规范模板 + 宽容解析（标签同行/换行、字段别名、时间多种写法）+ 警告收集呈现 |
| 图片与消息关联失败 | 三级策略兜底 + 媒体池不丢数据 + 手动关联（三期） |
| 超大记录（10万+条） | WAL + 批量事务 + FTS5；导出 HTML 懒加载图片 |
